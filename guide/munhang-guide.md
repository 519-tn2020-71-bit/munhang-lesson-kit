# 문항 수업 합본 지침

> **AI에게**: 이 파일 하나가 지침 전체다. 선생님이 모의고사 시험지와 해설지를 주면 이 지침대로 세트 데이터 파일(.mjs) 하나를 만든다. 선생님 PC에 Node.js가 없으면 문항 수업 HTML 파일 하나를 직접 만든다.
> 만들기 전에 인터뷰하고 설계표를 확인받는다. HTML을 직접 쓸 때 `<head>`의 여섯 줄은 그대로 둔다(지금 환경에서 안 열려도 교실 브라우저가 연다).
> 엔진 주소: munhang/munhang.css·js, munhang/kit.css·js, exploragram@2.8.1 (묶기 전에는 수업 파일 옆 munhang 폴더에 하네스 engine 폴더의 파일을 둔다)


# 문항 수업 하네스 (munhang)

선생님이 모의고사 **시험지와 해설지**를 주면 문항 풀이 수업용 HTML을 만든다. 판서·넘기기·반별 저장·자동 점검은 exploragram 엔진이, 지문 근거 연결과 선지 판정은 이 스킬의 `engine/munhang.js`가 맡는다. AI는 **시험의 글을 정확히 옮기고, 선지마다 근거를 잇고, 해설을 짧게 쓰는 일**만 한다.

수업 파일은 **세트 데이터 한 파일**(`assets/set-example.mjs` 꼴)을 쓰고 `scripts/gen.mjs`로 만든다. 기본 디자인은 국어 예시 양식(노란 테·흰 카드·테두리 제목 상자·파란 주석, `engine/ppt.css`)이고, 완성 예시는 저장소의 `examples/국어예시_도서분류법.html`이다. 부품 문법은 `references/parts.md`, HTML을 직접 쓸 때의 뼈대는 `assets/template.html`이다.

## 수업 흐름 (지문 세트 하나)

1. **지문 읽기** 장: 문단 2개 안팎씩. 문단 끝 꼬리표(`.mh-note.step`)를 →로 연다(화제, 개념 정의, 원리, 예시, 반론 …).
2. **구조도** 장: 문단마다 중심 내용 한 줄, 문단 사이 관계(`data-rel`)를 →로 하나씩 연다.
3. 문항마다 두 장:
   - **고르기** 장: 발문과 선지를 `.quiz`로. 반이 손을 들거나 말로 답을 정한 뒤 눌러 정답과 선지별 까닭을 본다.
   - **판정** 장(`.mh-judge`): 왼쪽은 문단 탭으로 넘기는 지문, 오른쪽은 선지를 →로 하나씩. 선지마다 「○ 맞다 / ✕ 틀리다」로 반의 예상을 고른 뒤 「판정과 근거」를 누르면 판정, 해설이 나오고 지문 근거 구절에 형광이 칠해진다.

## 절차

0. **자료 종류부터 확인한다.** 받은 자료가 모의고사·수능 시험지(와 해설지)면 아래 절차 그대로 간다. **활동지, 학습지, 교과서 본문**처럼 시험지가 아니면 다른 것을 묻기 전에 먼저 이렇게 묻고, 선생님이 고른 방식을 끝까지 그대로 따른다(섞지 않는다).
   > 시험지가 아니라 활동지(교과서 본문)네요. 어떻게 만들까요?
   > ① **문항을 만들어 풀기**: 본문으로 수능형 문항(발문·선지 5개·정답·해설)을 만들어, 지문 분석 → 고르기 → 선지 판정 → 정리로 풀어 봅니다.
   > ② **활동지 그대로(디지털 교과서)**: 활동지의 글·물음·표를 그대로 싣고, 빈칸은 눌러서 여는 칸으로, 서술형 물음은 학생이 적는 칸과 → 로 여는 예시 답으로 만듭니다.
   - **① 문항 만들기**를 고르면 더 묻는다: 몇 문항(추천: 본문 길이에 따라 2~4), 유형(내용 일치, 추론, <보기> 적용, 어휘, 표현), 난이도. 세트에 `madeQs: true`를 넣는다(고르기 장에 '자료로 만든 문항' 표시). 본문은 글자 그대로 `paras`에 옮기고, 문항은 `qs`에 시험 세트와 같은 꼴로 쓴다. 정답은 하나만 분명히 맞게, 오답은 본문의 한 군데를 비틀어 만들고 선지마다 본문 근거(`data-ev`)를 단다. 정답·해설은 AI가 만든 것이므로 전달 메모에 선생님 확인을 부탁한다. `exam`에는 '교과서 본문으로 만든 문항'처럼 출처를 적는다. 예시: `assets/set-example-made.mjs`.
   - **② 활동지 그대로**를 고르면 더 묻는다: 빈칸 답을 활동지·지도서에서 줄지, AI가 채울지(채우면 전달 메모에 표시), 서술형 예시 답을 넣을지, 학생이 직접 적는 칸을 둘지. 세트에는 `paras`·`qs` 대신 `sheet`(장 목록)를 쓴다. 활동지의 글·물음·표·순서를 고치지 않고 그대로 옮기며, 활동지 한 쪽이 화면에 넘치면 블록 단위로 장을 나눈다. 활동지의 빈칸 자리는 `{{답}}`, 교과서 본문의 핵심어를 가리고 싶을 때만 따로 묻고 `{{ }}`를 더한다. 블록 꼴(`text`, `q`, `quiz`, `table`, `box`, `img`)은 `scripts/gen.mjs` 위쪽 주석, 예시는 `assets/set-example-sheet.mjs`.
   - 두 방식 모두 양식(⑥)과 그림 넣기·검증(기준 13)은 시험지와 같다. 설계표 대신 ①은 `문항 | 유형 | 정답 | 근거 문단`, ②는 `장 | 활동지 쪽 | 블록 | 빈칸 수` 표로 확인받는다.

1. **읽기**
   - PDF: 그대로 읽는다(Claude Code는 Read로 쪽 그림까지 본다). 형광·밑줄·㉠ 같은 표시를 놓치지 않는다.
   - HWPX: `node scripts/hwpx2txt.mjs 시험지.hwpx 작업/시험지.txt`(코드를 돌릴 수 있을 때만). 구형 HWP는 열지 못하면 한글에서 HWPX나 PDF로 저장해 달라고 한다.
   - 해설지에서 **정답표**와 선지별 해설을 찾는다. 정답은 해설지가 기준이다.
2. **인터뷰.** 한 번에 묻는다. 짐작한 답에 (추천)을 붙이고 "알아서"라고 하면 추천대로 간다.
   ① 범위: 어느 문항(예: 18~21번), 한 차시인가 여러 차시인가
   ② 장면: 지문 읽기와 구조도를 넣을까(추천: 독서는 넣기, 문학은 작품 읽기로), 판정 장은 모든 문항인가 어려운 문항만인가
   ③ 반 자료: 문항별 정답률이나 많이 고른 오답이 있으면 받는다(있으면 고르기 장 뒤에 표로 넣는다)
   ④ 지킬 것: 그대로 둘 말, 뺄 문항, 학교 양식(머리 띠 글자)
   ⑤ **주석 자료**: 지문 주석 자료(EBS 주석 그림, 교사가 만든 지문 분석 PPT·HTML, 수업 노트 등)가 있는지 먼저 묻는다. 있으면 받아서 읽고, 주석을 어떻게 만들지 셋 중에서 고르게 한다.
      - **주석 자료만 그대로**: 자료의 주석과 형광만 옮긴다. AI는 주석을 새로 쓰거나 고치지 않는다. 자료에 없는 문장에는 주석을 달지 않는다.
      - **주석 자료 + AI 분석 추가(추천)**: 자료의 주석은 그대로 두고, 형광이 있는데 주석이 빠진 문장에 AI 주석을 더한다. 전달 메모에 AI가 더한 주석이 어디인지 적는다.
      - **AI 판단만**: 자료 없이 AI가 지문을 분석해 주석을 쓴다(자료가 없을 때의 기본값).
      고른 방식은 설계표 위에 한 줄로 적어 둔다.
   ⑥ **양식**: 학교나 선생님이 쓰는 PPT 양식이 있으면 올려 달라고 한다(PPT 파일이나 장 화면 캡처 한두 장). 받으면 바깥 테 색, 글자 색, 주석·강조 색, 지문 상자 테두리, 제목 상자 테두리, 글꼴을 읽어 세트의 `style`에 넣고 표지·지문 장 하나를 먼저 보여 확인받는다. 없으면 기본 양식(국어 예시)으로 간다(추천).
3. **설계표 확인.** 채팅에 보여 주고 "이대로 만들까요?"라고 묻는다. 칸: `지문 세트 | 문항 | 유형(내용 일치, 추론, <보기> 적용, 어휘 …) | 정답 | 매력적 오답과 까닭 | 넣을 장`. 매력적 오답은 해설지나 반 자료에 근거한다. 설계표는 HTML에 넣지 않는다.
4. **쓰기: 세트 데이터 → gen.mjs.** 아래 '기준'을 따라 세트 데이터 한 파일을 쓴다(`assets/set-example.mjs`의 꼴과 주석을 그대로 따른다: 지문 조각 `paras`, 형광 `[[n:구절]]`, 주석 `notes`, 전체 구조 `flow`, 어휘·개념 `vocab`·`concepts`, 구조도 `struct`, 문항 `qs`). 그다음 `node scripts/gen.mjs 세트.mjs --out 수업폴더`(코드를 돌릴 수 있을 때만)를 돌리면 표지 → 독해 포인트 → 지문 분석 → 전체 구조 → 어휘·개념 → 구조도 → 문항마다 고르기·판정·정리 장이 국어 예시 양식으로 만들어지고 한 파일로 묶인다. 장 나누기(높이 어림), ○✕와 정답의 맞물림, 주석 자리는 gen.mjs가 맡는다. HTML을 손으로 쓰지 않는다: 지문·주석·선지만 쓰므로 쓰는 양이 몇 분의 일이고, 양식이 늘 같다. 고칠 때도 세트 파일의 그 줄만 고치고 다시 돌린다(파일 전체를 다시 쓰지 않는다).
   - 코드를 돌릴 수 없는 채팅 AI: 세트 파일(.mjs)을 만들어 선생님께 주고, 선생님이 `node scripts/gen.mjs 세트.mjs`(코드를 돌릴 수 있을 때만)를 돌린다. 선생님 PC에 Node.js가 없으면 그때만 `assets/template.html` 뼈대로 HTML을 직접 쓴다(수업 파일 옆 `munhang/` 폴더에 `engine/` 파일들을 둔다).
   - 값이 바뀌는 지문의 익스플로라그램은 세트의 `explore: [{ title, html }]`로 넣는다.
5. **점검.** 코드를 돌릴 수 있으면 `node scripts/serve.mjs <폴더> 8782`(코드를 돌릴 수 있을 때만)로 띄우고 브라우저에서 `Munhang.check()`와 `Exploragram.audit()`를 돌린다. `Munhang.layout()`(글자가 제 칸을 벗어나 옆 글과 겹치는지, 흰 카드 밖으로 나가는지 장마다 잰다)까지 셋 다 0이 될 때까지 고친다. 표의 제목 칸, 범례, 단추처럼 좁은 칸의 긴 글자가 잘 겹친다. 판정 장은 선지마다 「판정과 근거」를 눌렀을 때 형광이 실제로 보이는지(근거가 두 곳이면 근거 모아 보기에 둘 다 나오는지)도 확인한다. 판정 장은 선지 몇 개의 「판정과 근거」를 눌러 형광 자리를 눈으로 본다.
   - 코드를 돌릴 수 없으면 전달할 때 부탁한다. "파일을 열었을 때 오른쪽 위에 빨간 「문항 점검 N」이나 툴바의 「점검 N」이 뜨면 눌러서 「AI에게 보낼 말 복사」 내용을 붙여 주세요."
   - **내용 검토.** 모양 점검이 0이 되면 `munhang-content-reviewer` 에이전트(하네스의 `agents/munhang-content-reviewer.md`를 `~/.claude/agents/`에 복사해 둔다)에게 시험지·해설지 PDF, 세트 데이터, 완성 HTML, 문항 범위를 주고 내용 검토를 맡긴다. 에이전트는 파일을 고치지 않고 `_work/review-<세트>.md` 보고서만 쓴다. 보고서의 「치명」과 「수정 권장」은 모두 반영하고 「참고」는 타당한 것만 고른 뒤, 다시 만들어 모양 점검을 한 번 더 돌린다(검토 반영으로 글이 늘면 장이 넘치기 쉽다). 익스플로라그램은 `node scripts/explore-eval.mjs <세트.mjs> <장 번호> [이름=값,…]`(코드를 돌릴 수 있을 때만)로 지문·<보기>의 수치 사례(예: 온오프비 10% → 4.5 V)를 넣어 모형이 같은 값을 내는지, 재생이 끝난 상태의 문장이 의도대로인지 직접 확인한다. 지문 주석이 정답을 미리 알려 주지 않는지도 이때 본다(주석은 정답 대신 질문으로 이끈다). 에이전트를 쓸 수 없는 환경이면 같은 검토 항목을 스스로 따진다.
6. **전달: HTML 한 파일.** gen.mjs는 만든 뒤 바로 묶는다. HTML을 직접 썼다면 `node scripts/bundle.mjs 수업.html --out 수업.html`(코드를 돌릴 수 있을 때만)로 그 자리에서 한 파일로 바꾼다(실시간 기능은 빼고 묶는다). munhang.css·js·ppt.css, 교실 도구 kit.css·kit.js(툴바 정리·떠 있는 타이머·폰 쓸어넘기기·화면 점검)와 엔진이 모두 파일 안에 들어가 폴더 없이 폰·메신저·USB 어디서 열어도 같게 보이고, 인터넷 없이도 열린다. munhang 폴더나 「-바로보기」 같은 두 벌을 따로 두지 않는다. 엔진은 처음 묶을 때 인터넷에서 한 번 받아 engine/vendor/에 두고 다시 쓴다(새 엔진은 vendor를 지우고 묶는다). 엔진·디자인을 고치면 파일을 다시 묶는다. 채팅에는 사용법, AI가 새로 쓴 해설과 판단, 확인할 곳, 저작권 안내를 쓴다.

## 기준

1. **시험의 글은 글자 그대로.** 지문, 발문, 선지, <보기>, 정답은 시험지와 해설지의 글을 바꾸지 않는다. 띄어쓰기와 문장 부호도 그대로 둔다. 읽어 낸 글자가 불확실하면 전달 메모에 적는다.
2. **해설은 짧게 새로.** 선지 해설(`.mh-why`)은 해설지 내용을 바탕으로 1~2문장으로 다시 쓴다. "~에 ~라고 했다", "~이므로 틀리다"처럼 근거와 판단을 말한다. 해설지에 없는 설명은 감싼 요소에 `data-ai="해설 보충"`을 붙인다.
3. **선지마다 근거.** `data-ev="문단|구절"`의 구절은 지문에서 **글자 그대로 복사**한다(공백 수는 달라도 된다). 근거가 여러 곳이면 `;`로 잇는다. 근거가 <보기>면 `보기|구절`. 근거가 지문 밖(배경지식, 어휘 사전 뜻)이면 가장 가까운 지문 구절을 걸고 해설에 밝힌다.
4. **판정과 정답이 맞물린다.** `data-ox`는 선지 내용이 맞으면 `o`, 틀리면 `x`다. 발문이 '적절한 것'이면 정답만 `o`, '적절하지 않은 것'이면 정답만 `x`다. 점검이 정답 번호와 발문으로 이것을 맞춰 본다. 고르기 장 `.quiz[data-q]`의 `data-ok` 자리도 정답 번호와 같아야 한다.
5. **문단은 420자 이하.** 넘으면 `data-para="2a"`, `"2b"`로 나누고 `data-label="2문단 ①"`처럼 탭 이름을 준다. 시는 연을 `data-para`로, 행 바꿈은 `class="mh-poem"`으로 살린다. (가)(나) 갈래 복합은 작품마다 `template`을 따로 두거나 `data-para="가1"`처럼 쓴다. <보기>도 420자를 넘으면 항목(◦)이나 문단별로 `data-para="보기1"`, `"보기2"`로 나누고 `data-label="〈보기〉 ①"`을 준다.
6. **교실 뒤에서 읽힌다.** exploragram 기준을 따른다: 본문 26px 안팎(판정 장 지문은 23px), 어떤 글자도 20px 미만 금지, 누르는 것 56px 이상. 넘치면 글자를 줄이지 말고 장을 나눈다. 고르기 장에 <보기>나 긴 자료가 있으면 `.mh-pair`로 왼쪽 자료, 오른쪽 선지로 둔다. <보기>가 300자를 넘으면 고르기 장 앞에 <보기> 읽기 장을 따로 두고(조각마다 한 장), 고르기 장에는 발문과 선지만 둔다. 고르기 장에서 선지가 길어 조금 넘치면 그 장만 선지 글자를 23px로 줄인다(`#장id .quiz .opt { font-size: 23px; }`).
7. **표와 그림.** 표는 HTML 표(`table.compare`)로 다시 친다. 그래프·도식은 단순하면 SVG로 다시 그리고, 아니면 `<figure class="fig">` 자리에 시험지 쪽 번호를 적은 설명(`alt`)을 남기고 전달 메모에 알린다. 외부 그림 주소는 쓰지 않는다.
8. **학생 화면에는 수업만.** '해설지에 따르면', 'AI가 정리함', 'PPT 3쪽' 같은 만드는 쪽 말을 쓰지 않는다. 출처는 '2025학년도 6월 모의평가 18번'처럼 학생이 찾을 수 있게 쓴다.
9. **엔진을 꼭 쓴다.** `<head>`의 여섯 줄(munhang.css, exploragram.css, kit.css, munhang.js, kit.js, exploragram.js)을 뼈대 순서대로 둔다. munhang.js가 exploragram.js보다 먼저여야 지문 복사 뒤에 엔진이 단계를 센다. 넘기기·판서·툴바를 직접 짜지 않는다. 장(`section.slide`)에 `display`를 주지 않는다.
10. **더 넣고 싶을 때.** 지문이 과학·경제 원리처럼 값이 바뀌는 내용이면 exploragram 지침(https://github.com/N-lifescience/exploragram)의 익스플로라그램을 지문 읽기 뒤에 한 장 더할 수 있다. 인터뷰에서 먼저 묻는다.
11. **지문 주석(PPT 양식).** 지문은 문장 단위로 끊고, 형광을 칠한 문장 바로 아래에는 반드시 파란 기울임 주석 한 줄을 단다. `→`는 역할·연결, `@`는 핵심·추론. 주석은 →를 누를 때마다 한 줄씩 나오게 한다(.step). 지문 주석에는 문항 번호나 정답("20번 정답", "(18번 ③)")을 쓰지 않는다. 선지와의 연결은 문제 풀이 장에서 한다. 주석 자료를 받았으면 인터뷰 ⑤에서 고른 방식을 따른다.
12. **타이머와 넘기기.** 타이머는 장에 넣지 않고 툴바 「타이머」로 여는 떠 있는 창이다(engine/kit.js. 문항 수업이 아닌 exploragram 수업도 `bundle.mjs`로 묶으면 똑같이 붙는다): 어느 장에서든 열고, 제목줄을 끌어 옮기고, 시작·멈춤·다시·±1분과 1·3·5·10분·이 세트 단추가 있다. 끝나면 빨갛게 깜빡이고 소리가 나며, 창을 닫아도 흐르고 툴바 단추에 남은 시간이 보인다. 처음 시간은 `<html data-mh-timer="초">`(세트 권장 시간: 문항당 독서 100초, 문학 90초, 30초 단위 올림. 세트의 `timer`로 바꾼다). 휴대폰에서는 장 위든 바깥 여백이든 좌우로 밀면 넘어간다(두 손가락 확대는 그대로). 이 공유판에는 실시간 수업(학생 기기가 교사 화면을 따라오고 답이 모이는 기능)이 없다. 묶기가 엔진의 실시간 부분을 떼어 내고, 외부 서버에 아무것도 보내지 않는다.
13. **시험지 그림 넣기.** 〈보기〉·지문·선지에 그림·표·도표가 있으면 글로 바꿔 쓰지 말고 잘라서 넣는다. ① `node scripts/serve.mjs <PDF가 든 폴더> 8784`(코드를 돌릴 수 있을 때만)와 `node scripts/pngsink.mjs <수업 폴더>/그림 8790`(코드를 돌릴 수 있을 때만)을 띄운다(서버 폴더 안에 scripts/pdfcrop.html이 보여야 한다). ② 브라우저로 `pdfcrop.html?pdf=/시험지.pdf&page=쪽&grid=1`을 열어 5% 눈금으로 자리(쪽에 대한 비율 x·y·w·h)를 찾는다. ③ `pdfcrop.html?pdf=..&page=..&x=..&y=..&w=..&h=..&scale=3&save=13_bogi.png`를 열면 그 폴더에 PNG로 저장된다. 잘린 그림을 눈으로 보고 윗줄 글자·상자 테두리가 들어오지 않게 다듬는다. ④ 조각 글에 `<img src="그림/13_bogi.png" alt="그림 설명">`을 넣는다. 묶기(bundle.mjs)가 그림을 파일 안에 넣는다(한 파일 유지). ⑤ **그림 검증(빠뜨리지 않는다).** 묶은 뒤 브라우저에서 `Munhang.check()`의 `mh-img*`(열리지 않음, 외부 주소, alt 없음)와 `Munhang.layout()`의 `mh-img-out`·`mh-img-spill`·`mh-img-blur`(카드 밖 잘림, 옆 글 덮음, 늘어나 흐림)을 0으로 만든다. 그다음 `Munhang.figures()`로 그림 목록을 뽑아, 그림이 든 장마다 화면을 찍어 시험지 그 쪽과 나란히 대 본다: 그림이 빠짐없이 들어갔는지(시험지의 그림·도표 수와 목록 수가 같은지), 맞는 그림이 맞는 자리(지문·<보기>·선지)에 있는지, 윗줄 글자나 상자 테두리가 끼거나 그림 끝이 잘리지 않았는지, 글씨가 읽히는지. 코드를 돌릴 수 없으면 전달 메모에 그림 목록(장 번호, 시험지 쪽)을 적고 선생님께 확인을 부탁한다. pdfcrop.html은 pdf.js를 인쇄용(intent: 'print')으로 그려 창이 가려져 있어도 멈추지 않는다. 자리 찾기는 눈금 스크린샷 대신 쪽 전체를 `x=0&y=0&w=1&h=1&scale=1&save=_p쪽.png`로 저장해 그림을 읽고 비율을 재면 빠르다(다 쓰면 지운다). 여러 장은 한 페이지 안에서 숨긴 iframe으로 pdfcrop 주소를 차례로 열고 제목이 'done'이 될 때까지 기다리면 한 번에 자를 수 있다. 그림은 한 장 높이를 거의 차지하므로 조각 하나에 그림 하나만 두고, 선지가 긴 문항의 〈보기〉 그림은 따로 한 장으로 보낸다. 그림이 지나치게 길면(통계+인터뷰+기사처럼) 그림 부분만 자르고 글은 옮겨 적는다.
14. **옛한글.** 아래아 등 옛한글은 첫가끝 조합(예: ᄌᆞ = U+110C U+119E)으로 쓴다. 맑은 고딕에서 한 음절로 모여 보이는지 글자 폭으로 확인한다(‘ᄌᆞ갸’ 폭 = ‘자갸’ 폭). 옛한글이 많은 〈보기〉 자료는 그림으로 자른다.

## 길이

- 지문 세트 하나 = HTML 한 파일. 40장을 넘어도 차시별로 나누지 않는다(목차로 옮겨 다닌다). 세트가 여럿이면 세트마다 한 파일.
- 장 수 어림: 지문 읽기 2~3장 + 구조도 1장 + 문항마다 2장.

## 전달 메모에 쓸 것

- 사용법: ① 더블클릭해 연다 ② 툴바에서 펜을 고르고 → ←로 넘긴다 ③ 판정 장에서 →로 선지를 넘기고, 반 학생들의 예상을 ○✕로 고른 뒤 「판정과 근거」를 누른다 ④ 폰·태블릿에서는 화면을 좌우로 밀어 넘긴다.
- 확인 부탁: AI가 새로 쓴 해설(`data-ai`), 흐린 쪽에서 읽은 글자, 근거 구절을 고른 판단.
- 저작권: "시험 지문과 문항이 들어 있으니 수업용으로만 쓰고 인터넷에 공개하지 마세요."

# 문항 수업 부품 사전

munhang.js가 동작을 붙인다. 수업 HTML에는 구조와 `data-*` 속성만 쓴다. 넘기기, 판서, 단계(`.step`), 단계 막대(`.reveal`), 문제(`.quiz`)는 exploragram 엔진의 부품이다(https://github.com/N-lifescience/exploragram 의 부품 사전).

## 0. 머리 여섯 줄 (순서를 지킨다)

```html
<link rel="stylesheet" href="munhang/munhang.css">
<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/N-lifescience/exploragram@2.8.1/engine/exploragram.css">
<link rel="stylesheet" href="munhang/kit.css">
<script defer src="munhang/munhang.js"></script>
<script defer src="munhang/kit.js"></script>
<script defer src="https://cdn.jsdelivr.net/gh/N-lifescience/exploragram@2.8.1/engine/exploragram.js"></script>
```

- `<html data-deck="mock-2025-06-18-21">`: 판서 저장 열쇠. 영문 소문자·숫자·하이픈으로 시험과 문항 범위마다 다르게.
- `<body data-theme="ppt">`, 장은 `<section class="slide" id="고정-id" data-sec="묶음" data-title="목차 이름">`.

## 1. 지문 `template.mh-src`

지문은 파일 안에 **한 번만** 쓴다. 읽기 장과 판정 장이 여기서 복사해 간다.

```html
<template class="mh-src" id="s18" data-title="[18~21] 다음 글을 읽고 물음에 답하시오.">
  <p data-para="1">첫 문단 글 그대로 …<span class="mh-note step">화제</span></p>
  <p data-para="2a" data-label="2문단 ①">둘째 문단 앞부분 …</p>
  <p data-para="2b" data-label="2문단 ②">둘째 문단 뒷부분 …</p>
  <div data-para="보기" class="mh-bogi"><p>&lt;보기&gt; 글 그대로 …</p></div>
</template>
```

- `data-para`: 문단 열쇠. 숫자면 탭 이름이 'N문단'이 되고, 아니면 `data-label`이나 열쇠 자체가 이름이 된다. 한 지문 안에서 겹치지 않는다.
- 한 조각 420자 이하(점검 `mh-long-para`). <보기>도 마찬가지로 `보기1`, `보기2`로 나눈다.
- 시험지의 ㉠, ⓐ, [A], 밑줄은 그대로 쓴다. 밑줄은 `<u>`, 네모 칸은 `<span style="border:2px solid">`.
- `.mh-note.step`: 읽기 장에서 →로 여는 문단 꼬리표(화제, 정의, 원리, 예시, 반론, 결론 …). 판정 장에서는 저절로 빠진다. AI가 붙인 꼬리표이므로 template에 `data-ai="문단 꼬리표"`를 붙인다.
- 시: `<p data-para="1" class="mh-poem">` 안에서 줄을 그대로 바꾼다(줄바꿈 문자 유지).

## 2. 지문 읽기 `.mh-read`

```html
<section class="slide" id="s18-read1" data-sec="18~21번 지문" data-title="1~2문단">
  <h2>문단마다 무엇을 말할까?</h2>
  <div class="mh-read" data-src="s18" data-paras="1-2"></div>
</section>
```

- `data-paras`: `1-2`, `3,4`, `2a,2b`, `보기`처럼 고른다. 빼면 전부.
- 지문 제목(`data-title`)은 저절로 붙는다. 둘째 장부터는 `data-title="off"`.
- 26px로 한 장에 600자 안팎이 들어간다. 넘치면 장을 나눈다.

## 3. 구조도 `ol.mh-map`

```html
<ol class="mh-map">
  <li class="step"><b>1문단</b><span>화제 제시: …</span></li>
  <li class="step" data-rel="원리 설명"><b>2문단</b><span>…</span></li>
  <li class="step" data-rel="반론과 보완"><b>3문단</b><span>…</span></li>
</ol>
```

- `data-rel`은 앞 문단과의 관계(구체화, 원리 설명, 예시, 대조, 반론, 보완, 평가, 결론 …). 문단 5개 안팎이면 한 장에 든다.
- 중심 내용은 AI가 쓰므로 `ol`에 `data-ai="구조도"`를 붙인다. 해설지에 '지문 분석'이 있으면 그것을 따른다.

## 4. 고르기 `.quiz[data-q]` (응답 모으기)

```html
<section class="slide" id="q19-poll" data-sec="19번" data-title="19번 고르기">
  <h2>19. 윗글을 이해한 내용으로 적절하지 않은 것은?</h2>
  <div class="quiz" data-q="19">
    <button class="opt" data-why="2문단에 그대로 나온다.">선지 ① 글 그대로</button>
    …
    <button class="opt" data-ok data-why="맞다. …이므로 틀린 설명이다.">선지 ③ 글 그대로</button>
    …
  </div>
</section>
```

- 선지 순서는 시험지 그대로(엔진이 번호 ①~⑤를 붙이므로 선지 글에 번호를 넣지 않는다).
- `data-ok`는 정답 하나. `data-why`는 한 문장.
- <보기>나 자료가 있으면 `<div class="mh-pair"><div class="mh-read" data-src="s18" data-paras="보기" data-title="off"></div><div class="quiz" data-q="21">…</div></div>`.
- 문항이 여럿이면 정답 자리가 같다는 `quiz-spot` 경고가 날 수 있다. 시험 순서를 지킨 것이므로 그대로 둔다.

## 5. 선지 판정 `.mh-judge`

```html
<section class="slide" id="q19-judge" data-sec="19번" data-title="19번 선지 판정">
  <h2>선지마다 근거를 찾아보자</h2>
  <div class="mh-judge" data-src="s18" data-q="19" data-answer="3" data-paras="1-4">
    <div class="mh-view"></div>
    <div class="mh-side">
      <p class="mh-stem">19. 윗글을 이해한 내용으로 적절하지 않은 것은?</p>
      <div class="reveal" data-stops="시작|①|②|③|④|⑤">
        <p data-only="0" style="font-size:24px">→를 누르면 선지가 하나씩 나온다.</p>
        <div class="mh-ch" data-only="1" data-ox="o" data-ev="2|지문에서 그대로 복사한 구절">
          <p class="mh-ct">① 선지 글 그대로</p>
          <p class="mh-why">2문단에 ~라고 했다.</p>
        </div>
        … ② ~ ⑤도 같은 꼴 …
      </div>
    </div>
  </div>
</section>
```

- `data-answer`: 정답 번호(해설지 정답표). `data-q`: 문항 번호(고르기 장과 같게).
- `data-paras`: 탭으로 보일 문단(빼면 전부). 관계없는 다른 지문 문단은 빼서 탭을 줄인다.
- `.mh-ch`: 선지 하나. `data-only`는 단계 막대 칸 번호(1~5). `data-ox`, `data-ev`, `.mh-ct`, `.mh-why`를 꼭 쓴다.
- 「○ 맞다 / ✕ 틀리다 / 판정과 근거」 단추와 판정 줄은 munhang.js가 붙인다. 직접 쓰지 않는다.
- 근거 문단 탭에는 노란 점이 찍히고, 첫 근거 문단이 열리며 구절에 형광이 칠해진다.
- 선지 글이 길어 넘치면 글자를 줄이지 말고 `data-paras`로 탭 수를 줄이거나, 판정 장을 두 장(①~③, ④~⑤)으로 나눈다. 두 장 모두 같은 `data-q`, `data-answer`를 주고, 둘째 장은 `data-stops="시작|④|⑤"`, 선지마다 `data-n="4"`처럼 원래 번호를 준다(`data-only`는 1, 2로 다시 센다). 점검은 같은 `data-q`의 장을 묶어 다섯 개를 센다.

## 6. 반 자료(선택)

```html
<table class="compare"><thead><tr><th>선지</th><th>①</th><th>②</th><th>③</th><th>④</th><th>⑤</th></tr></thead>
<tbody><tr><th>고른 비율</th><td>5%</td><td>12%</td><td class="ans">61%</td><td>18%</td><td>4%</td></tr></tbody></table>
```

선생님이 준 자료만 쓴다. 지어내지 않는다.

## 7. 점검 코드 `Munhang.check()`

| 코드 | 뜻 | 고치는 법 |
|---|---|---|
| `mh-src`, `mh-paras` | 지문 template이 없거나 고른 문단이 없음 | `data-src`, `data-paras` 철자 |
| `mh-dup-para` | 한 지문에 같은 `data-para`가 둘 | 열쇠를 다르게 |
| `mh-long-para` | 문단 조각이 420자 초과 | `2a`, `2b`로 나눈다 |
| `mh-answer`, `mh-stem`, `mh-choices` | 정답 번호·발문 없음, 선지가 5개가 아님 | 해설지 정답표, 발문 |
| `mh-ox` | 선지에 `data-ox` 없음 | `o` 또는 `x` |
| `mh-ox-key` | `data-ox`가 정답 번호·발문과 맞지 않음 | 정답과 발문('적절하지 않은')을 다시 본다 |
| `mh-why` | 해설 없음 | `.mh-why` 한두 문장 |
| `mh-ev` | 근거 없음, 문단 없음, 구절이 지문에 글자 그대로 없음 | 지문에서 구절을 다시 복사 |
| `mh-quiz-key` | 고르기 장의 정답 자리가 `data-answer`와 다름 | `data-ok` 자리 |
| `mh-img` | 그림 src가 없거나 외부 주소 | 시험지에서 잘라 `그림/` 폴더에 두고 묶는다 |
| `mh-img-alt` | 그림 설명(alt) 없음 | 무엇을 잘랐는지와 시험지 쪽(예: "13번 〈보기〉 그래프, 6쪽") |
| `mh-img-broken` | 그림이 열리지 않음 | 파일 이름, `그림/` 폴더, 묶기를 확인 |

화면 점검 `Munhang.layout()`은 그림도 잰다: `mh-img-out`(카드 밖으로 나가 잘림), `mh-img-spill`(제 칸을 벗어나 옆 글을 덮음), `mh-img-blur`(원래 크기보다 1.5배 넘게 늘어나 흐림 → `scale=3`으로 다시 자른다). `Munhang.figures()`는 장마다 그림 목록(장 번호, alt, 원래 크기, 열림 여부)을 준다. 시험지 쪽과 하나씩 대 볼 때 쓴다.

엔진 점검(`Exploragram.audit()`, 툴바 「점검」)도 함께 0으로 만든다. 넘침(`slide-overflow`)은 장을 나눠 고친다.
